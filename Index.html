System Overview

Aegis is a multi-layer Host-based Intrusion Detection System designed to monitor student and lab devices on WCE's campus network. It addresses the security gap between Sophos firewall (network perimeter) and device-level behavior. Sophos sees traffic; Aegis sees what generates it.

Core problem: WCE ERP is protected by CAPTCHA only. Result portal uses OTP (interceptable). Sophos firewall is perimeter-only — blind to compromised devices on the LAN. Aegis adds endpoint visibility.
Layer 1
Android Agent
Kotlin app on student phones. Evil twin detection, security score, ERP gated access, Sophos auto-login, threat reporting.
Layer 2
PC Agent
Java 17 daemon on lab computers. File integrity monitoring, process monitoring, network traffic scanning.
Layer 3
Backend Server
Spring Boot 3 + RabbitMQ. Ingests telemetry, scores devices, fires alerts, pushes to dashboard via WebSocket.
Layer 4
Admin Dashboard
React 18 + TypeScript. Live threat map, device health board, alert feed, analytics, policy manager.

Android Agent

Module 1
Evil Twin Detector
BroadcastReceiver on NETWORK_STATE_CHANGED. On WiFi connect, fetches current BSSID via WifiManager. Cross-checks against hardcoded list of legitimate WCE MAC addresses. Fires CRITICAL alert if rogue AP detected. Does NOT block connection (requires system-level perms). Notifies user + reports to server.
WifiManagerBroadcastReceiver
Module 2
Security Score Engine
Calculates 0–100 score. Formula: start 100, deduct: -30 rooted, -20 developer options on, -15 screen lock disabled, -10 per unwhitelisted dangerous-permission app (max -25), -5 unknown BSSID. Runs on WorkManager periodic task (every 30 min). Score stored locally + synced on heartbeat.
PackageManagerSettings.Secure
Module 3
Sophos Auto-Login
Fires on WiFi connect event. OkHttp POST to Sophos captive portal at 192.168.1.8:8090/userLogin with encrypted credentials from Keystore. Headers: Content-Type: application/x-www-form-urlencoded. No manual portal interaction needed. Logs success/failure to Room DB.
OkHttpWorkManagerKeystore
Module 4
ERP Secure WebView
WebView with FLAG_SECURE (blocks screen capture). Gated by score threshold (configurable from server policy, default ≥ 60). Score below threshold → access denied screen with reason. Auto-fills ERP credentials from Keystore. Clears WebView cache on app background.
WebViewFLAG_SECUREscore gate
Module 5
Threat Reporter
Packages events as ThreatEventDTO JSON. POSTs to /api/v1/threats/report with JWT auth. Runs in WorkManager. On network failure, stores event in Room DB and retries with exponential backoff (1s, 2s, 4s, max 60s). Flushes local queue on next successful connection.
RetrofitRoom bufferbackoff
Module 6
Local Storage & Encryption
Android Keystore + AES-256-GCM for credential encryption. Room DB with two tables: local_events (offline buffer), app_whitelist (server-pushed). SharedPreferences for device UUID + JWT token (EncryptedSharedPreferences). Zero plaintext credentials ever written to disk.
Keystore APIRoomEncryptedSharedPrefs

PC Agent

Core Module 1
File Integrity Monitor (FIM)
On first run, generates SHA-256 baseline of watched directories (configurable, default: /etc, /bin, /usr/bin on Linux; C:\Windows\System32 on Windows). Stores hashes in H2 embedded DB. WatchService listener detects CREATE/MODIFY/DELETE events. On change: recomputes hash, diffs against baseline, fires alert if mismatch. Smart debounce: batch events within 5s window, ignore .tmp/.log extensions.
WatchServiceSHA-256H2/SQLite
Core Module 2
Process Monitor
ProcessHandle.allProcesses() snapshot every 60s. Diffs against previous snapshot. Flags new processes matching suspicious patterns: unexpected powershell.exe, cmd.exe spawned by non-user, curl/wget on Windows, nc (netcat), python -c (one-liner execution). JNA for Windows: checks process parent PID for privilege escalation detection.
JNAProcessHandle API
Core Module 3
Network Connection Scanner
Parses netstat output (no Pcap4J — avoids root requirement). Monitors active TCP connections every 30s. Flags: connections to IPs in local blocklist (AbuseIPDB cached daily), port scan behavior (>10 unique destination IPs in 60s), outbound data spike (tracked via /proc/net/dev on Linux or WMI on Windows). Reports anomalies to server.
netstat parsingAbuseIPDB
Core Module 4
Event Queue & Reporter
In-memory LinkedBlockingQueue buffers events. Batch-flushes every 30s or on CRITICAL event (immediate). OkHttp POST to /api/v1/threats/report with JWT. Exponential backoff on failure. Local H2 table keeps encrypted forensic trail (last 1000 events, 7-day retention). On agent start: replays unsent events from local DB.
OkHttpJacksonH2 forensic log

Backend Server — Spring Boot 3

Layer
REST API (Spring MVC)
Device registration, telemetry ingestion, threat reporting, policy retrieval, admin operations. JWT authentication on all endpoints. Rate limiting: 60 req/min per device via Spring's Bucket4j or a simple Redis counter.
Layer
Message Broker (RabbitMQ)
API receives event → publishes to queue → returns 202 immediately. Consumer processes asynchronously. Decouples burst ingestion from DB writes. Separate queues for different event priorities.
Layer
Analysis Engine
RabbitMQ @RabbitListener consumers. Applies weighted rule engine to compute device score. Triggers ERP policy block if score < threshold. Correlates events for Patient Zero detection. Pushes WebSocket message to dashboard on alert.
Layer
Data Layer
PostgreSQL for persistent storage (all events, devices, policies). Redis for real-time device state cache (current score, online/offline, last seen). Flyway for schema migrations — clean setup on every fresh deploy.

RabbitMQ Queue Design

Exchange: aegis.events (topic exchange)  ·  All queues have DLQ (dead-letter queue)  ·  Management UI: http://localhost:15672
aegis.telemetry.events
Routing key telemetry.#
Producer AgentController (heartbeat)
Consumer TelemetryConsumer
Priority LOW

Processes periodic heartbeats. Updates device score in DB. Updates Redis cache with current device state. Triggers ERP block if score drops below threshold. Low priority — can queue during burst without impacting UX.

aegis.threat.alerts
Routing key threat.#
Producer ThreatController
Consumer ThreatAlertConsumer
Priority HIGH

Processes threat reports. Persists event to security_events table. Applies rule engine to compute severity escalation. Triggers WebSocket push to dashboard. Runs Patient Zero correlation. High priority — processed before telemetry.

aegis.score.updates
Routing key score.#
Producer ThreatAlertConsumer (internal)
Consumer ScoreUpdateConsumer
Priority MEDIUM

Recomputes device score after a threat event. Updates devices.current_score. Updates Redis. Broadcasts score update WebSocket message to dashboard. Separate queue ensures score recalculation doesn't block threat processing.

// RabbitConfig.java — bean declarations
@Bean
Queue telemetryQueue() {
    return QueueBuilder.durable("aegis.telemetry.events")
        .withArgument("x-dead-letter-exchange", "aegis.dlx")
        .build();
}

@Bean
TopicExchange aegisExchange() {
    return new TopicExchange("aegis.events");
}

@Bean
Binding telemetryBinding(Queue telemetryQueue, TopicExchange aegisExchange) {
    return BindingBuilder.bind(telemetryQueue)
        .to(aegisExchange).with("telemetry.#");
}

Admin Dashboard

Panel 1
Live Threat Map
Leaflet.js campus satellite map. Markers for reported rogue APs (EVIL_TWIN events). Color-coded by severity. Click marker → device detail panel. Real-time via WebSocket /topic/alerts.
Panel 2
Device Health Board
shadcn/ui DataTable. All enrolled devices. Live score badges (React Query 30s refetch). Filter by dept / risk / type. One-click block ERP. Bulk policy push.
Panel 3
Alert Feed
Real-time WebSocket stream. Each card: device name, event type, severity badge, timestamp. Acknowledge / escalate / dismiss. Browser sound on CRITICAL. Toast notification.
Panel 4
Patient Zero Tracker
Clusters threats by time window. Shows first-infected device, spread timeline, affected device count. Visual spread graph using Chart.js. Helps isolate infection source fast.
Panel 5
Analytics
Chart.js line + bar charts. Daily/weekly alert volume, score distribution histogram, top threat types pie chart, per-department risk ranking. Export to PDF/CSV.
Panel 6
Policy Manager
Set ERP min score threshold. Manage known BSSID list. Manage app whitelist. Changes pushed to all agents via /admin/policy PUT → RabbitMQ broadcast → agents pull on next heartbeat.

Security Design

Authentication
  • Agents: JWT (HS256, 24h expiry) + refresh token rotation
  • Admin: JWT (HS256, 8h expiry) stored in httpOnly cookie (not localStorage)
  • Separate signing secrets for agent tokens vs admin tokens
  • JWT revocation via Redis blocklist on logout / device unenroll
  • Rate limit: 60 req/min per device UUID via Redis counter
Transport Security
  • All API calls over HTTPS — nginx handles SSL termination
  • Certificate pinning on Android (OkHttp CertificatePinner)
  • Certificate pinning on PC agent (OkHttp)
  • HSTS header enforced by nginx
  • WebSocket connection over WSS (secure WebSocket)
Credential Storage
  • Android: Keystore + AES-256-GCM — hardware-backed on supported devices
  • Android: EncryptedSharedPreferences for JWT + device UUID
  • PC agent: OS keychain (Windows Credential Manager / libsecret on Linux)
  • Server: bcrypt for admin passwords (strength 12)
  • Zero plaintext credentials ever logged or sent over network
Server Hardening
  • nginx: only ports 80 + 443 exposed externally
  • All other services (PostgreSQL, RabbitMQ, Redis) on Docker bridge network only
  • Spring Security: CORS restricted to dashboard origin only
  • Input validation via @Valid on all DTOs
  • JSONB payload size limit: 4KB per event

Privacy Design (DPDP Act 2023)

India's Digital Personal Data Protection Act 2023 requires informed consent for processing personal data. Aegis is designed for compliance: pseudonymous IDs, behavior-only monitoring, explicit consent, data minimization.
What Aegis collects
  • Device UUID (pseudonymous — not name or student ID by default)
  • Security score + breakdown (root status, dev options, screen lock)
  • App permission flags (which dangerous permissions granted, not content)
  • WiFi BSSID (AP identifier, not browsing activity)
  • Network connection endpoints (IPs + ports, not payload)
  • File system change events (path + hash, not file content)
  • Process names + PIDs (not command arguments containing user data)
What Aegis never collects
  • SMS or call content
  • Browser history or browsing activity
  • Photos, camera, or microphone access
  • Location (GPS coordinates)
  • File content (only hashes for integrity)
  • Keystrokes or input
  • Any data from outside the Aegis app sandbox
Consent requirement: First screen on enrollment must display clear summary of data collected and obtain explicit acceptance. Store consent_accepted = true + timestamp in devices table. Without this field, device registration fails.
